# RSNA Knee Abnormality Detection 2026 — архитектурный план

Дата: 2026-09-15. Дедлайн входа и слияния команд: **15.10.2026**, финальный сабмит: **22.10.2026**. Осталось 5 недель.

## 1. Задача и ограничения

| | |
|---|---|
| Вход | Исследование МРТ колена: 3–14 серий DICOM (sag/cor/ax; PD/T2/T1, с FS и без), 11–320 срезов в серии |
| Выход | 12 вероятностей на исследование: ACL, MCL, медиальный/латеральный мениск, OA медиальный/латеральный/пателлофеморальный, выпот, синовит, киста Бейкера, контузия, перелом |
| Метрика | macro ROC-AUC (12 меток с равным весом → редкие метки решают столько же, сколько частые) |
| Train | ~4 400 исследований, 819k DICOM, 570 ГБ. Gold-разметка только у ~58. У остальных только текст отчёта на ~12 языках |
| Test | скрытый, ~1 300 исследований, 16–19 клиник, без отчётов |
| Сабмит | Kaggle Notebook, ≤ 9 ч, без интернета, GPU Kaggle (T4×2 / P100), `submission.csv` |
| Призы | $77k, отдельный трек за эффективность модели |

## 2. Ключевые тезисы (на чём выигрывается соревнование)

1. **Качество меток важнее архитектуры.** Train-метки почти целиком получаются из отчётов. Тест размечен экспертами. Значит, нужен экстрактор, который воспроизводит именно экспертное определение каждой находки, и 58 gold-исследований используются как калибровочный набор для экстракции, а не как обучающая выборка.
2. **Сдвиг между клиниками.** Случайные фолды завышают AUC примерно на 0.05: модель учит сигнатуру сканера. Валидация только с группировкой по fingerprint сканера (производитель | модель | версия ПО | частота | катушка).
3. **Редкие метки (перелом, контузия, синовит) стоят 1/12 метрики каждая.** Нужны: мягкие метки с весами, взвешенный сэмплер, attention-агрегация вместо mean pooling (перелом виден на 2–3 срезах).
4. **9 часов на ~1 300 исследований** — это ~25 с на исследование, включая декодирование JPEG2000. Бюджета хватает на ансамбль из 3–5 моделей с TTA, но пайплайн обязан деградировать плавно (страховка по времени встроена в `infer.py`).
5. **Итерации.** Полный проход по 570 ГБ DICOM — часы. Поэтому один раз строится компактный кэш (JPEG-in-npz, ~1 МБ на серию), а первые модели обучаются на замороженных фичах foundation-модели за минуты.

## 3. Схема пайплайна

```
train_images (DICOM)             train.csv (Report, 58 gold)
      │                                  │
scan_metadata ──► meta.parquet     extract_labels (LLM: Claude Opus 5 batches | локальный Qwen3 через vLLM)
      │      (plane, seq, fingerprint)   │            + rules.py (мультиязычные правила, кросс-чек)
build_cache ──► cache/*.npz        make_label_table ──► label_table.parquet  (soft y, веса, gold override)
      │                                  │            └─ калибровка порогов по 58 gold
      └──────────────┬───────────────────┘
               make_folds (StratifiedGroupKFold по fingerprint)
                     │
         ┌───────────┴─────────────┐
   extract_features (DINOv2)   train.py (end-to-end 2.5D)
   + study transformer              │
         └───────────┬─────────────┘
              OOF / ансамбль / TTA
                     │
      infer.py в Kaggle-ноутбуке (DICOM → те же preprocess_series → модели → submission.csv)
```

## 4. Блоки и инструменты

### 4.1 Данные и DICOM (`rsna_knee/dicom.py`, `series_select.py`, `preprocess.py`)
- **pydicom 3 + pylibjpeg (+openjpeg, libjpeg)**: в датасете четыре transfer syntax, включая JPEG Lossless и JPEG 2000. Декодирование проверяется тестом `test_jpeg2000_roundtrip`. Для ускорения в ноутбуке опционально `dicomsdl` или `nvidia-nvimgcodec` (GPU-декодер JPEG2000).
- Порядок срезов по `ImagePositionPatient` вдоль доминирующей оси нормали (LPS), не по имени файла и не по `InstanceNumber`. Направление сортировки поэтому одинаково для всех клиник (sag: справа налево, cor: спереди назад, ax: снизу вверх) — модель может выучить латеральность по анатомии (малоберцовая кость = латерально).
- Обработаны: `RescaleSlope/Intercept`, `MONOCHROME1`, multi-frame, разные матрицы внутри серии, dual-echo серии (PD+T2 в одной серии → оставляем одно эхо).
- Плоскость — из `ImageOrientationPatient`; тип последовательности — из `SeriesDescription` (мультиязычные сокращения: DP, FatSat, SPAIR, TIRM, «жироподавление») с фолбэком на физику (TE/TR/TI). Колонки CSV `Fluid_Sensitive`/`Fat_Suppression` не используются как источник истины.
- Нормализация интенсивности — перцентили 0.5–99.5 на серию → uint8. Letterbox-resize до 384.
- Выбор серий: по плоскости лучшая fluid-sensitive + FS серия, локалайзеры и 3D-объёмы штрафуются; политика `core3` (3 серии) для старта и `rich` (до 6) для сильных моделей. Одна функция `preprocess_series` используется и в кэше, и в инференсе — гарантия одинаковых пикселей train/test.

### 4.2 Метки из отчётов (`rsna_knee/reports/`)
- **Схема извлечения**: на каждую из 12 находок `status ∈ {present, absent, equivocal, not_mentioned}`, `severity`, `detail` (подтип: complete tear / partial / root tear / mucoid / healed…), `evidence` (цитата). Плюс язык, латеральность, prior_surgery. Это позволяет менять пороги (считать ли trace effusion, partial tear, degenerative signal) без повторного прогона LLM.
- **Промпт** содержит точные радиологические определения каждой метки и правила негации/шаблонных фраз («ligaments intact» → ACL и MCL absent).
- **Бэкенды**: 
  - `AnthropicBackend`: Claude Opus 5, structured outputs (JSON-schema), prompt caching системного промпта, Message Batches API (−50 % стоимости; ~4 400 отчётов ≈ $50–60).
  - `OpenAICompatBackend`: локальная open-weight модель через vLLM (Qwen3-32B-AWQ, Apache-2.0, 119 языков) или DeepSeek. **Правила Kaggle запрещают передавать данные соревнования третьим лицам** — если формулировка в Rules это покрывает, используем локальную модель на Kaggle T4×2 (интернет в тренировочных ноутбуках разрешён) и не отправляем отчёты во внешний API. Проверить пункт Rules до запуска.
  - `rules.py`: мультиязычный regex-экстрактор (13 языков), для аудита расхождений и фолбэка.
- **Калибровка по gold**: `evaluate_mapping` печатает AUC/accuracy маппинга против 58 gold; `calibrate` перебирает per-label пороги (значение not_mentioned, equivocal, минимальная severity) с защитой от переобучения (`min_gain`). Gold-метки перекрывают LLM-метки с весом 5.
- **Веса в лоссе**: present/absent 1.0, equivocal 0.5 (таргет 0.5), not_mentioned 0.4 (таргет = априор метки, для OA выше). Это мягкая weak-supervision без выброса данных.

### 4.3 Модель (`rsna_knee/models/study_transformer.py`)
Иерархический трансформер уровня исследования:
1. **Slice encoder**: 2.5D (3 соседних среза → RGB) + timm backbone. Стартовый: `tf_efficientnetv2_s` (Apache-2.0, быстрый). Сильные: `convnext_small.fb_in22k_384` (MIT), `eva02_base_448` (MIT), `vit_base_patch14_dinov2` (Apache-2.0). DINOv3/ConvNeXt-V2 — лицензионный риск для призового решения, проверять Rules.
2. **Series transformer**: 2 слоя над срезами серии + синусоидальная позиция среза (нормированная координата вдоль нормали) + эмбеддинги плоскости и типа последовательности.
3. **Study transformer**: 2 слоя над всеми токенами всех серий исследования (переменное число серий, маскирование отсутствующих плоскостей) + study-токен.
4. **Label queries**: 12 обучаемых запросов делают cross-attention ко всем срезам (query2label/DETR) → каждая метка сама выбирает нужную плоскость и срезы; focal-находки не размываются усреднением. Attention-карты дают интерпретацию (какие срезы дали «перелом»).
5. Лосс: BCE с мягкими таргетами и весами. Режим `feature_dim>0` — обучение только агрегатора на предвычисленных фичах (минуты на фолд).

### 4.4 Обучение (`rsna_knee/train.py`)
- AdamW, раздельные lr для backbone/головы, cosine с warmup, AMP (bf16 на A100/H100, fp16 на T4), EMA весов, grad-clip, gradient checkpointing для 384 px.
- Аугментации одинаковы для всех срезов серии: аффинные (±10°, 0.9–1.1, сдвиг 5 %), hflip (анатомически валидно: перевёрнутое правое колено выглядит как левое), яркость/контраст/гамма, шум, random erasing. По оси срезов — случайный под-диапазон и джиттер.
- Сэмплер с бустом исследований, положительных по редким меткам (`(1/prevalence)^0.5`).
- На каждой эпохе: OOF-предсказания, macro AUC по weak-меткам, по «уверенным» меткам (явные present/absent) и отдельно по gold-подмножеству; чекпоинты `best.pt`/`last.pt`, resume после обрыва 9/12-часовой сессии Kaggle.

### 4.5 Валидация (`rsna_knee/cv.py`)
`StratifiedGroupKFold`: группы = fingerprint сканера, стратификация = самая редкая положительная метка (+ gold-флаг, чтобы gold были в каждом фолде). Целевая корреляция: OOF macro AUC ↔ public LB. Public LB — дополнительный, но шумный сигнал (часть 1 300 исследований).

### 4.6 Инференс (`rsna_knee/infer.py`, `kaggle/inference_notebook.py`)
- Датасеты-вложения: код, веса фолдов (`config.yaml`, `best.pt`, `priors.json`), wheels для офлайн-pip.
- Заголовки серий сканируются в пуле потоков, DICOM декодируется в воркерах DataLoader параллельно с GPU.
- Ансамбль фолдов/бэкбонов + hflip-TTA. Страховка по времени: при прогнозе превышения бюджета отключается TTA, затем сбрасываются члены ансамбля. Исследование без пригодных серий получает train-априор, а не crash.
- Efficiency-трек: отдельный сабмит с одной моделью (EfficientNetV2-S или ConvNeXt-Nano, 256–320 px, без TTA), дистиллированной из ансамбля.

## 5. Вычисления

| Вариант | Что даёт |
|---|---|
| Kaggle (30 GPU-ч/нед, T4×2) | Достаточно для feature-пути и 1–2 end-to-end модели/неделю. Два фолда параллельно: по одному процессу на GPU |
| Облако (A100/H100, $2–3/ч, Lambda/RunPod/Vast) | Полный кэш за ~2 ч, end-to-end фолд 384 px за ~1 ч. Рекомендуется для недель 3–4 |
| Локально (WSL, без GPU) | Только CSV, отчёты, экстракция меток, EDA, тесты |

Оценка: 4 400 × 3 серии × 24 среза = 317k изображений/эпоху; EfficientNetV2-S @384 на T4 ≈ 150 img/s → ~35 мин/эпоха, 8 эпох × 5 фолдов ≈ 24 GPU-ч. На A100 в 4–5 раз быстрее.

## 7. Риски и меры

| Риск | Мера |
|---|---|
| Определение меток экспертами ≠ формулировкам отчётов (partial tear, trace effusion, degenerative signal) | Схема с severity/detail, калибровка на gold, мониторинг per-label AUC на LB |
| Правила запрещают внешний LLM API | Локальный Qwen3 через vLLM на Kaggle GPU (бэкенд уже есть) |
| Лицензии предобученных весов | Список Apache/MIT-бэкбонов в `models/backbone.py`; DINOv3 только после проверки Rules |
| Сдвиг клиник на тесте | Grouped CV, per-series нормализация, сильные интенсивностные аугментации, ансамбль по бэкбонам |
| Падение на нестандартном DICOM в тесте | Загрузчик с фолбэками, `try/except` на серию, априор при полном отказе, тест на JPEG2000 |
| Превышение 9 ч | Замер throughput на 50 исследованиях перед сабмитом, автоматический сброс TTA/ансамбля |
| Малые редкие метки → шумная OOF | Metric по «уверенным» меткам, gold-подмножество, усреднение по фолдам, не гнаться за 0.005 |

## 9. Ближайшие действия

1. Принять правила на Kaggle, проверить пункты про внешние данные/API и лицензии.
2. Скачать `train.csv`, `train_series.csv`, `sample_submission.csv` (только CSV) и прогнать `extract_labels.py --backend rules-only`, посмотреть распределение языков и находок.
3. Запустить `scan_metadata.py` + `build_cache.py` в Kaggle-ноутбуке, выгрузить кэш как датасет.
4. Запустить LLM-экстракцию, получить таблицу согласия с gold, выбрать маппинг.
5. `extract_features.py` (DINOv2-B) → `train.py --config configs/feat_dinov2.yaml` → первый сабмит.
